Part II - Core Canvas HTML Standards

Canvas strips most modern CSS and all JavaScript. Write HTML as if you have no stylesheet.

Core Rule: Every element that needs visual formatting must carry its own inline style="" attribute. There are no external stylesheets. Write as if you have no stylesheet at all.

What Canvas Actually Strips (per Official Allowlist)

Verified against the Canvas HTML Editor Allowlist. Some properties that older internal notes described as "stripped" are in fact allowed - the real issue is often a rendering quirk, not removal.

ItemActual Canvas Behavior

<style>...</style> blocksNot in the allowlist. Behavior is inconsistent - sometimes preserved, often stripped when the page is saved or re-edited. Do not rely on embedded style blocks.
<script>Removed. All JavaScript is stripped for security. Not in the allowlist.

The flex-with-icons gotcha: Canvas's allowlist permits display: flex, but icon images placed inside a flex container can render inconsistently across Canvas themes, mobile views, and offline exports. Use a two-column table with role="presentation" for any icon-plus-text callout. Combined with the <img>-from-GitHub icon source rule (Part XXI), the table layout is the reliable pattern across every Canvas build.

Part III - Accessibility Requirements

UVU must comply with Section 508 and WCAG 2.1 Level AA. Every page, assignment, and quiz must meet these rules.

2.1 Images - Alt Text Required

Every <img> tag must have an alt attribute. Alt text must be under 120 characters (Canvas flags anything longer).

<!-- Informational image -->
<img src="waveform.png"
     alt="Sine wave showing one complete cycle at 440 Hz"
     style="max-width:100%; height:auto;">

<!-- Decorative image -->
<img src="divider.png" alt="" role="presentation">

2.2 Headings - Proper Hierarchy

Never use <h1> inside a Canvas Page body. Canvas provides H1 from the page title automatically. Your content starts at H2. Never skip levels (H2 to H4 without H3). H3 as the first heading on a page is a Severe Panorama error.

2.3 Links - Descriptive Text and Title Required

Never use "click here" or "read more." All links must carry a title attribute. Links that open new tabs must warn the user.

2.4 Tables - Data vs. Layout

Table TypeRequired Treatment
Data table (rubrics, specs, comparisons)Must have <caption> (plain text, no style), <thead> with <th scope="col">, and <tbody>. This is the ONLY allowed use of <table>.
Layout table (side-by-side icon+text, callouts, banners)Deprecated as of 2026. Use <div> with inline <img style="vertical-align:middle"> instead. Even role="presentation" tables are flagged by Canvas Panorama.
Numbered checklist or stacked rowsUse stacked <div> elements with alternating background colors. Never <table>, never display:table.

Critical Panorama Rule: Canvas Panorama scans every <table> tag for missing headers and captions regardless of role="presentation". Even CSS-table-emulating divs (display:table, display:table-cell) are flagged. To pass Panorama with zero issues, layout patterns must use plain <div> with inline images and position:absolute for offset elements.

Caption Note: Canvas strips visually-hidden caption CSS. For data tables, use a plain <caption> tag with NO style attribute. <caption> and <th scope="col"> are always required together - missing either one is a separate flagged error. A two-column comparison table with labeled headers is a data table, not a layout table.

Why "What to Submit" is locked at the bottom: Students should be able to scroll to the end of any assignment page and find exactly which files to upload, without preparation steps mixed in. All preparation belongs in "Before You Submit" above the green rule. The 3px green rule + banner is the visual signal that the deliverables list begins, and the colored rows let students visually match icon shape + tint to each file they are uploading.

The "What to Submit" banner ALWAYS uses Submit_Upload.svg at 66×66. Never Action_Deadline. Never any other submission icon. Never 44×44. The banner is the one place on the page where the program-standard 44×44 icon size is intentionally broken to make this section unmistakable. Per-row icons inside the section stay at 44×44 and use the file-specific icon (Submit_Session, Submit_Audio, Submit_PDF, etc.).

Use an <hr> for the green rule, not an empty <div>. Canvas strips empty divs on paste. Use <hr style="border:none; border-top:3px solid #1B5E20; margin:0;">. The hr is a void element and survives. Both the hr and the banner div need margin:0 on their touching edges so the rule sits flush against the banner top.

21.1 The Icon Specification Rule

Every icon used in Canvas HTML is an <img> tag. The src attribute is always a GitHub raw URL pointing to a file under Classes/All/DAPR_Canvas_Icon_Reference/. Never use inline <svg> tags in Canvas page HTML - they are not used in this program even though Canvas technically allows them.

Required attributes on every icon <img> tag:

  • src - the full raw GitHub URL (see Part XXIV for every icon's URL)
  • alt - short descriptive text matching the icon's meaning ("Required", "Note", "Warning", etc.) or alt="" if the surrounding label text already names the callout type
  • width and height - 44 is the program standard for callouts, section headers, checklist row icons, and submit-item icons. Use 20 only for tiny inline icons next to a single word inside a paragraph (rare).
  • style="vertical-align:middle; margin-right:10px;" when the icon sits inline next to text in a section header or callout (always required - the div-only layout depends on this for alignment)

The icon files themselves are designed at viewBox="0 0 24 24" with stroke-width="2.2", stroke-linecap="round", and stroke-linejoin="round". These are properties of the source SVG file on GitHub, not attributes you write in your Canvas HTML. You only write the <img> tag.

Sizing Update (April 2026): The previous standard had three sizes (22 in callouts, 36 standalone, 20 inline). After student feedback that 20-22 px icons were too small to identify quickly, the program standard is now 44x44 for all visible icons. The only exception is genuinely inline icons next to a single word, which stay at 20x20.

Don't repeat the same icon on every row. When a section has many checklist rows, place ONE 44x44 icon in the section header and use plain numbered div rows below. Repeating the same icon (Action_Checklist) on every row drains it of meaning. Per-row icons are reserved for distinct file types or distinct actions, such as the What to Submit section using Submit_Session for the zip and Submit_Audio for the WAV.

25.6 Common Mistakes on This Section

MistakeFix
Banner uses Action_Deadline or Submit_Audio or some other icon Always Submit_Upload.svg. The banner icon never changes per assignment.
Banner icon at 44×44 66×66. The banner is the one program-wide exception to the 44×44 standard.
Banner background is a different green or has a gradient Solid #1B5E20. White text. border-radius:0 0 6px 6px only.
All rows have the same color Color is locked to icon type per the §25.3 table. Cyan/teal for sessions, grey-blue for non-session zips, purple/violet for WAV, dark indigo for .ptx-only, olive for PDF, orange for video, forest green for generic upload.
Using Submit_Download.svg in any context That filename does not exist in the program. There is no submit-a-download. Files going TO the student use Action_Download.svg in the body of the page. Files going FROM the student use the appropriate Submit_* icon.
Submit_Upload at 44×44 used for the banner header Banner is 66×66. Submit_Upload at 44×44 is the generic upload row for unusual file types (.pages, .xml, .sib, .als, screenshots) - never the banner.
Visible gap between the green hr and the banner Both must have margin:0 on the touching edge. hr uses margin:0; banner uses margin:0 0 16px 0.
Trailing paragraph after the last row ("Once submitted...") Delete it. The final colored row is the last thing on the page.
Naming convention or "test your zip" callout inside What to Submit Move to Before You Submit. What to Submit is upload action items only.
Before You Submit missing one of its three sub-blocks Always: File Naming Convention (Required) → Test your zip (Warning) → Pre-submit checklist (Action_Checklist + ul). All three. In that order.

For lab-only assignments (single PDF, no session): the same banner pattern applies, but the rows below are reduced to whatever the assignment actually requires - often just the PDF row (olive). For unusual deliverables not covered by a specific Submit_* icon - .pages, .xml, .sib, .als, .logicx, screenshots, plain text - use Submit_Upload as a generic upload row at 44×44 with the forest green spec. The banner header itself never changes regardless of how many rows follow or what those rows contain.
