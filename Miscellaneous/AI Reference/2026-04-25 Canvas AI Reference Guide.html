Part II - Core Canvas HTML Standards

Canvas strips most modern CSS and all JavaScript. Write HTML as if you have no stylesheet.

Core Rule: Every element that needs visual formatting must carry its own inline style="" attribute. There are no external stylesheets. Write as if you have no stylesheet at all.

What Canvas Actually Strips (per Official Allowlist)

Verified against the Canvas HTML Editor Allowlist. Some properties that older internal notes described as "stripped" are in fact allowed - the real issue is often a rendering quirk, not removal.

ItemActual Canvas Behavior
<link rel="..."> (external CSS)Removed. Not in the allowlist.
<style>...</style> blocksNot in the allowlist. Behavior is inconsistent - sometimes preserved, often stripped when the page is saved or re-edited. Do not rely on embedded style blocks.
<script>Removed. All JavaScript is stripped for security. Not in the allowlist.
<h1>Removed. Only h2 through h6 are in the allowlist. Canvas provides the H1 from the page title.
display: flexAllowed per the allowlist. However, image and icon elements placed inside a flex container can render inconsistently across Canvas themes and offline exports. Use <table role="presentation"> for icon + text callout layouts. Reserve flex for non-icon content if you use it at all.
display: gridAllowed per the allowlist. Not all Canvas themes render it predictably at narrow widths. Use tables with percentage widths if the layout must be identical in every Canvas build.
position: absolute / fixedAllowed per the allowlist. Avoid anyway because Canvas page chrome (sidebar, banners) can overlap absolutely positioned content unpredictably.
@font-face / Google FontsNot in the allowed style properties list. Use system fonts (Arial, Georgia, Courier New).
CSS custom properties (--var)Not supported by the RCE in a reliable way. Inline hex codes directly.
rgba() color valuesRender but make WCAG contrast harder to verify. Use hex codes.
class= (custom classes)Class attribute is preserved on elements, but Canvas does not ship a stylesheet that matches author-defined class names. Pair every class with an inline style attribute or skip the class.

The flex-with-icons gotcha: Canvas's allowlist permits display: flex, but icon images placed inside a flex container can render inconsistently across Canvas themes, mobile views, and offline exports. Use a two-column table with role="presentation" for any icon-plus-text callout. Combined with the <img>-from-GitHub icon source rule (Part XXI), the table layout is the reliable pattern across every Canvas build.

Part III - Accessibility Requirements

UVU must comply with Section 508 and WCAG 2.1 Level AA. Every page, assignment, and quiz must meet these rules.

2.1 Images - Alt Text Required

Every <img> tag must have an alt attribute. Alt text must be under 120 characters (Canvas flags anything longer).

<!-- Informational image -->
<img src="waveform.png"
     alt="Sine wave showing one complete cycle at 440 Hz"
     style="max-width:100%; height:auto;">

<!-- Decorative image -->
<img src="divider.png" alt="" role="presentation">

2.2 Headings - Proper Hierarchy

Never use <h1> inside a Canvas Page body. Canvas provides H1 from the page title automatically. Your content starts at H2. Never skip levels (H2 to H4 without H3). H3 as the first heading on a page is a Severe Panorama error.

2.3 Links - Descriptive Text and Title Required

Never use "click here" or "read more." All links must carry a title attribute. Links that open new tabs must warn the user.

2.4 Tables - Data vs. Layout

Table TypeRequired Treatment
Data table (rubrics, specs, comparisons)Must have <caption> (plain text, no style), <thead> with <th scope="col">, and <tbody>.
Layout table (side-by-side columns)Must have role="presentation". No caption, no th tags.
Decorative list (items stacked vertically)Use <div> elements. Avoids all table accessibility issues.

Caption Note: Canvas strips visually-hidden caption CSS. Use a plain <caption> tag with NO style attribute. <caption> and <th scope="col"> are always required together - missing either one is a separate flagged error. A two-column comparison table with labeled headers is a data table, not a layout table.

6.6 QTI Item Title Rule

Set the title attribute on every <item> to the question bank or category name. All questions in the same category share the exact same title string. Do not use the question text as the title. Example: title="Network Wiring Standards" on every question in that bank.

  xmlns="http://www.imsglobal.org/xsd/imsccv1p1/imscp_v1p1">
  <metadata>
    <schema>IMS Content</schema>

  </metadata>
  <organizations/>
  <resources>
    <resource identifier="ASSESSMENT_001"
             type="imsqti_xmlv1p2"

    </resource>
  </resources>
</manifest>

Part X - Using AI to Build Canvas Content

Master Prompt for Canvas HTML Pages

Paste this at the start of every AI session before generating Canvas content. Works with Claude, ChatGPT, Gemini, and any other AI tool.

You are generating HTML for Canvas LMS (Instructure). Canvas strips most
modern CSS and all JavaScript. Follow these rules exactly:

HTML RULES:
- All CSS must be inline style="" attributes. No <style> blocks, no external CSS.
- Layout: use HTML tables with role="presentation" for side-by-side columns.
  For vertical lists of items, use stacked <div> elements, not tables.
- Fonts: Arial, Georgia, or Courier New only. No Google Fonts.
- No CSS Grid, no Flexbox, no CSS variables, no JavaScript.
- Use hex color codes. Never use rgba().
- Do not include navigation links to standalone HTML files.
- No em dashes and no double dashes (--) in visible content.
  Use a hyphen with spaces ( - ) where a dash is needed in text.
- Do not use manual numbered labels (1. 2. 3.) inside div elements
  when items convey a sequence. Use word-based labels instead.

ICON RULES (mandatory - see DAPR Reference Guide Part XXI and Part XXIV):
- Every icon is an <img> tag pointing to the DAPR GitHub icon library.
- Never use inline <svg> tags for icons in Canvas page HTML.
- Base URL for every icon:
  https://raw.githubusercontent.com/uvu-dapr/Canvas/main/Classes/All/DAPR_Canvas_Icon_Reference/

  Action_External_Link.svg, Action_Peer.svg

  Feedback_Best(_white).svg

CALLOUT BOX RULES:
- Use only the six approved callout types: Required (green), Note (blue),
  Warning (yellow), Critical (red - filename Callout_Avoid.svg), Tip (purple), FAQ (pink).
- Build callouts as a 2-cell <table role="presentation"> with the icon img in cell 1

ACCESSIBILITY RULES (Canvas checker must show 0 issues):
- First heading in content area must be <h2>. Never use <h1>.
- All <img> tags need alt="description" or alt="" for decorative.
  Alt text must be under 120 characters.

  <thead> with <th scope="col">, and <tbody>.

- Text color must pass WCAG 4.5:1 contrast on its background.
  Safe colors on white: #212121, #0D47A1, #1B5E20, #993300, #B71C1C.

QUIZ RULES (when generating QTI):

- Each distractor must stand independently.
- All assessments must be self-grading. No essay questions.

OUTPUT FORMAT:
- Output only the HTML that goes inside the Canvas content editor body.
- Do not include <!DOCTYPE>, <html>, <head>, or <body> tags.

All AI-generated content must sound like it was written directly by the course instructor.

Part XXI - Canvas Icon and Callout Box System

Standardized icons hosted on GitHub and color-coded callout boxes for all DAPR Canvas HTML pages. Every icon on every Canvas page is referenced via an <img> tag pointing to the GitHub raw URL. No inline SVG is used in Canvas page HTML.

Icon Source Authority - The Single Rule: Every icon on every Canvas page is an <img> tag with src set to a raw URL under https://raw.githubusercontent.com/uvu-dapr/Canvas/main/Classes/All/DAPR_Canvas_Icon_Reference/. Never use inline SVG. Never upload icon files to Canvas. Never link to github.com page URLs. The raw URL is the only acceptable source.

Required: Every Canvas page that uses a callout box must use one of the six approved types below. Custom colors, custom icon shapes, and custom border styles are not permitted. An AI generating Canvas HTML must reference this section and Part XXIV to produce the correct GitHub raw URL, hex codes, and border colors for each callout type.

21.1 The Icon Specification Rule

Every icon used in Canvas HTML is an <img> tag. The src attribute is always a GitHub raw URL pointing to a file under Classes/All/DAPR_Canvas_Icon_Reference/. Never use inline <svg> tags in Canvas page HTML - they are not used in this program even though Canvas technically allows them.

Required attributes on every icon <img> tag:

  • src - the full raw GitHub URL (see Part XXIV for every icon's URL)
  • alt - short descriptive text matching the icon's meaning ("Required", "Note", "Warning", etc.) or alt="" if the surrounding label text already names the callout type
  • width and height - 22 inside callout boxes, 36 for standalone email/contact icons at the bottom of pages, 20 for inline use next to a single line of text
  • style="vertical-align:middle;" when the icon sits inline next to text in a flowing paragraph

The icon files themselves are designed at viewBox="0 0 24 24" with stroke-width="2.2", stroke-linecap="round", and stroke-linejoin="round". These are properties of the source SVG file on GitHub, not attributes you write in your Canvas HTML. You only write the <img> tag.
