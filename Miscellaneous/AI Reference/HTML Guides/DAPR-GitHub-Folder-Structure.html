Canvas Naming System: Option D (Permanent Standard)

ALL Canvas modules and pages across all 12 DAPR courses use Option D naming. No other system is in use.

Module title pattern: Topic: M# - Descriptive Title (Week ##)

Page name pattern: Topic: Descriptive Page Title

The three rules:

Rule 1 - Module title carries the topic prefix, module number, descriptive title, and week in parentheses. Example: Sound: M2 - Sound and Hearing (Week 02)

Rule 2 - Page name carries only the topic prefix and a plain descriptive title. No module number. No week. No part number. Example: Sound: Read Sound and Hearing

Rule 3 - At semester rollover, update only the week parenthetical in module titles if pacing changed. Never rename pages. Pages have no week reference and require zero rollover maintenance.

GitHub Folder Naming System

Why underscores instead of PascalCase: Underscores were chosen because they make word boundaries explicit and unambiguous at a glance. In a string like DigitalAudioEssentials it is genuinely hard to know where one word ends and the next begins, especially in technical contexts like HTML where everything may already be capitalized. Underscores act as visible spaces: Digital_Audio_Essentials reads immediately. They are also trivially reversible -- replace underscores with spaces to recover the original title, or remove them entirely to collapse the name. No parsing rules required. PascalCase was specifically avoided because it produces inconsistent results when acronyms like MIDI, DHCP, or EQ appear in names, and because it is hard to apply consistently without making errors.

Underscores replace spaces within any name
Every space in a folder or filename becomes an underscore. First letter of each word is capitalized (title case).

Address_Resolution_Protocol
Sound_Wave_Properties
Dynamic_Based_Processing
Pro_Tools_Cleanup
Digital_Audio_Essentials
Spatial_Audio_I
Double hyphens separate course number from title
Course folder: single hyphen between DAPR and the number, double hyphen before the title. The double hyphen makes the boundary visually obvious at a glance.

DAPR-2000--Digital_Audio_Essentials
DAPR-2000L--Digital_Audio_Essentials_Lab
DAPR-3255--Audio_Hardware2
DAPR-3010R--Digital_Lecture_Series
DAPR-3345--Spatial_Audio_II

Three-level folder structure (course-specific images):
Classes / DAPR-####--Course_Name / Topic / Page_Title / Image_File.jpg

Level 1 = Course folder matching GitHub exactly. Level 2 = Topic word from the Canvas page topic prefix (e.g., Networking, MIDI, Sound, Jobs). Level 3 = Page title folder, matching the Canvas page descriptive title exactly with spaces replaced by underscores. All image files for that Canvas page go directly inside the Level 3 folder. No further subfolders. No module number anywhere in the path -- modules are intentionally excluded because moving a page between modules must never break an image URL.

Raw URL Pattern

https://raw.githubusercontent.com/uvu-dapr/Canvas/main/Classes/DAPR-2000--Digital_Audio_Essentials/Sound/The_Decibel/Filename.jpg https://raw.githubusercontent.com/uvu-dapr/Canvas/main/Classes/DAPR-3255--Audio_Hardware2/Networking/Address_Resolution_Protocol/Filename.jpg https://raw.githubusercontent.com/uvu-dapr/Canvas/main/Classes/All/Pro_Tools_Cleanup/Before.jpg

Always use raw.githubusercontent.com not github.com. Verify every new URL in Safari or Chrome before building the Canvas page. You should see the image with nothing else around it. Image filenames follow the same Title_Case_With_Underscores pattern as folder names.

All/ - Shared Across Multiple Courses

Classes/All/ - Images used in pages across multiple courses (no topic subfolder layer)
  • Classes/All/Pro_Tools_Cleanup/
  • Classes/All/DAPR_Canvas_Icon_Reference/
  • Classes/All/Page_Title_Name/ add new shared folders as needed -- title case with underscores, no topic layer inside All/

Use Classes/All/ only when the exact same image is needed on pages across two or more different courses. Classes/All/ skips the topic subfolder layer -- page-title folders sit directly inside Classes/All/. If an image is used in only one course it belongs in that course folder even if the topic is general.

The Six Questions - Asked Every Time Images Are Involved

Question 1
Is this image shared across multiple courses, or does it belong to one specific course? Shared across courses = Classes/All/    One course only = Classes/DAPR-####--Course_Name/
Question 2
What is the exact course folder name as it appears in GitHub under Classes/? (e.g., DAPR-2000--Digital_Audio_Essentials, DAPR-3255--Audio_Hardware2). Must match GitHub exactly including capitalization.
Question 3
What is the Canvas page topic prefix? This becomes the Level 2 topic folder. Example: "Networking: Address Resolution Protocol" has topic prefix Networking, so Level 2 = Networking/. For All/ content, skip this question -- there is no topic layer.
Question 4
What is the Canvas page descriptive title (everything after the colon)? This becomes the Level 3 page-title folder. Replace every space with an underscore, preserve title case, drop any parenthetical acronym. Example: "Dynamic Host Configuration Protocol (DHCP)" becomes Dynamic_Host_Configuration_Protocol/.
Question 5
What are the exact filenames of every image pushed to the repository for this page? List them all before writing any HTML. Filenames follow the same Title_Case_With_Underscores convention as folder names.
Question 6
Have these files been committed and pushed in GitHub Desktop? Confirm the push completed and verify at least one raw URL loads correctly in Safari or Chrome before writing a single img tag.

Never rename or move an image file or folder after its URL has been used in a Canvas page. Canvas pages contain hardcoded raw URLs. Renaming a file or folder breaks every page that references it with no error message and no warning. If a Canvas page is renamed and you want the folder to match, every img src URL on that page must be updated manually. To update an image without breaking anything, replace the file in place using the exact same filename.
