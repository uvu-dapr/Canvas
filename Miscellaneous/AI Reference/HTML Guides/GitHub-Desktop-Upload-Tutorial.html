How to Upload Folders and Files to GitHub Desktop

uvu-dapr/Canvas repository  |  DAPR Program  |  GitHub Desktop on macOS  |  Updated April 2026

How GitHub Desktop works: GitHub Desktop is a visual interface for Git. It watches a folder on your Mac (the local repository). When you add, change, or delete files in that folder using Finder, GitHub Desktop sees the changes automatically. You then write a short summary and click two buttons to send those changes to GitHub. That is the entire workflow.

Part 1 - The Three Locations You Need to Understand

Your Mac (Local Repository)

A regular folder on your Mac that GitHub Desktop is watching. For this program, the path is:

/Users/adamwolson/Library/CloudStorage/Dropbox/apps/GitHub/Canvas/

This folder is synced by Dropbox AND tracked by Git. When you add files here in Finder, GitHub Desktop notices them immediately.

GitHub (Remote Repository)

The online copy at:

github.com/uvu-dapr/Canvas

This is what Canvas pages actually read from when they load your images. Changes only appear here after you Commit and Push from GitHub Desktop.

The golden rule: Files are only live on GitHub - and therefore visible in Canvas - after you have completed both steps: Commit to main and Push origin. Adding files to the Finder folder alone does not make them live.

Part 2 - One-Time Setup (Only Do This Once)

1
Download and install GitHub Desktop

Go to desktop.github.com and download GitHub Desktop for Mac. Install it like any other Mac app. Sign in with your GitHub account when prompted.

2
Clone the repository to your Mac

Cloning creates a local copy of the GitHub repository on your Mac that GitHub Desktop can track.

Option A - If the folder already exists at the Dropbox path: In GitHub Desktop, go to File > Add Local Repository and navigate to the Canvas folder. If GitHub Desktop recognizes it as a Git repository, you are done.

Option B - Starting fresh: In GitHub Desktop, go to File > Clone Repository. Search for uvu-dapr/Canvas. For the local path, choose:

/Users/adamwolson/Library/CloudStorage/Dropbox/apps/GitHub/

GitHub Desktop will create a Canvas folder at that path automatically.

3
Confirm the repository is active in GitHub Desktop

The repository name Canvas should appear in the top-left dropdown of the GitHub Desktop window. The main panel should say "No local changes" when nothing has been modified. If you see this, setup is complete.

Part 3 - The Daily Workflow (Adding Images and Folders)

Every time you need to add images to the repository - whether it is a new assignment folder or more files for an existing one - follow these steps in order.

1
Open Finder and navigate to the Canvas repository folder

In Finder, navigate to:

/Users/adamwolson/Library/CloudStorage/Dropbox/apps/GitHub/Canvas/

You will see the top-level course folders: All/, DAPR2000-DigitalAudioEssentials/, DAPR2000L-DigitalAudioEssentialsLab/, and so on.

2
Create the subfolder for your assignment (if it does not exist yet)

Images must always be inside an assignment subfolder - never placed directly in a course folder. Navigate into the correct course folder, then create a new folder named after the assignment. Follow the naming rule: lowercase, hyphens between segments, underscores within concept words, no spaces.

Examples of correct subfolder names:

eq_lab compression_lab essential_groundwork spatial_mix_final m02-p3-sound_wave_properties

To create the folder: in Finder, press Shift + Command + N, or right-click and choose New Folder. Type the name exactly as shown above.

3
Copy your image files into the subfolder

Drag or copy your .jpg screenshot files into the subfolder you just created. Image filenames must be lowercase with underscores (no spaces, no capital letters, no hyphens within a single word).

Correct filename examples:

plugin_settings.jpg session_overview.jpg bounce_dialog.jpg eq_screenshot_before.jpg eq_screenshot_after.jpg

Incorrect: Screenshot 2026.jpg   EQ Lab Before.jpg   screenshot1.jpg

4
Open GitHub Desktop - your new files appear automatically

Switch to GitHub Desktop. The left panel (Changes) will list every file you just added. Each file has a green plus icon next to it, indicating it is new. You do not need to click anything to make them appear - GitHub Desktop detects them automatically.

If the changes panel is empty, make sure the correct repository (Canvas) is selected in the top-left dropdown.

5
Write a commit summary

At the bottom-left of the Changes panel, there is a Summary field. Type a short description of what you are adding. Keep it to one line. Examples:

Add eq_lab images for dapr-2000l Add spatial_mix_final screenshots for dapr-3345 Add Essential Groundwork images for dapr-2020l

The Description field below it is optional. Leave it blank.

6
Click "Commit to main"

Click the blue Commit to main button at the bottom of the left panel. This saves a snapshot of your changes to your local repository history. The files are now tracked by Git on your Mac, but not yet live on GitHub.

After clicking, the Changes panel will show "No local changes" - this is correct and expected.

7
Click "Push origin"

At the top of the GitHub Desktop window, click the Push origin button. This sends your committed changes to GitHub. After the push completes, the button label changes back to "Fetch origin."

Your images are now live. The raw URLs are active immediately.

8
Verify one URL in a browser before building the Canvas page

Before writing any img tags, paste one of your new raw URLs into Safari or Chrome. You should see the image with nothing else around it. If you see the GitHub file browser page instead, you used the wrong URL format.

Correct URL format:

https://raw.githubusercontent.com/uvu-dapr/Canvas/main/COURSE/SUBFOLDER/filename.jpg

Example:

https://raw.githubusercontent.com/uvu-dapr/Canvas/main/dapr-2000l/eq_lab/plugin_settings.jpg

Wrong - this shows the GitHub file page, not the image:

https://github.com/uvu-dapr/Canvas/blob/main/dapr-2000l/eq_lab/plugin_settings.jpg

Part 4 - Uploading Your Existing Local Folder Structure

You already have class folders organized on your Mac (visible in the screenshot you shared). Here is how to get all of them into the repository at once.

1
Look at your existing folder names vs. the repository naming convention

Your existing folders use the format DAPR2000L-DigitalAudioEssentialsLab - capital D, capital letters throughout the course name portion. The zip file provided with this tutorial contains empty folders with these exact names pre-built for you to use as a starting structure.

Note that the GitHub repository uses a different convention for image subfolders (lowercase with hyphens), but the top-level course folder names match your local naming format.

2
Copy the course folders into the Canvas repository folder

In Finder, copy your class folders (or the pre-built empty ones from the zip) into:

/Users/adamwolson/Library/CloudStorage/Dropbox/apps/GitHub/Canvas/

After copying, the Canvas folder should contain:

Canvas/
    All/
    DAPR2000-DigitalAudioEssentials/
    DAPR2000L-DigitalAudioEssentialsLab/
    DAPR2010-CoreRecording/
    DAPR2010L-CoreRecordingLab/
    DAPR2020-CoreMixing/
    DAPR2020L-CoreMixingLab/
    DAPR2080-PodcastAndRadioProduction/
    DAPR2255-AudioHardwareI/
    DAPR3010R-DigitalLectureSeries/
    DAPR3255-AudioHardwareII/
    DAPR3340-SpatialAudioI/
    DAPR3345-SpatialAudioII/
3
GitHub cannot commit empty folders - use .gitkeep files

Git ignores empty folders entirely. If a course folder has no files in it, it will not appear in GitHub after you push. The zip file provided already includes a hidden .gitkeep file inside each empty folder. This is a zero-byte placeholder file that Git will track, which forces the folder to appear in the repository even when it has no images yet.

When you later add real image files to a folder, you can delete the .gitkeep - it is no longer needed once there are real files present.

4
Switch to GitHub Desktop - commit and push everything at once

GitHub Desktop will show all the new folders and files in the Changes panel. You can commit them all in a single commit. Use a summary like:

Add all 12 DAPR course folders with initial structure

Click Commit to main, then Push origin. All folders are now live on GitHub.

Part 5 - Adding the DAPR-Canvas-Icon-Reference Folder

Your Dropbox path already has this folder at:

/Users/adamwolson/Library/CloudStorage/Dropbox/apps/GitHub/Canvas/All/DAPR-Canvas-Icon-Reference/

Since it is already inside the Canvas repository folder on your Mac, GitHub Desktop should already be tracking it. Check the Changes panel - if the folder and its files appear there, just commit and push. If it does not appear (because GitHub Desktop has not seen changes since your last push), go to Repository > Push or make a small change to trigger a new commit.

The DAPR-Canvas-Icon-Reference folder is in the All/ subfolder. Because it contains icons used across multiple courses, it belongs in All/ rather than a specific course folder. Its raw URL pattern is:
https://raw.githubusercontent.com/uvu-dapr/Canvas/main/All/DAPR-Canvas-Icon-Reference/filename.svg

Part 6 - Quick Reference Summary

Task What to Do
Add images for a new assignment Create subfolder in Finder > copy .jpg files in > open GitHub Desktop > write summary > Commit to main > Push origin
Update an existing image Replace the file in Finder using the exact same filename > GitHub Desktop shows it as modified > Commit and Push
Add a new course folder Create the folder in Finder inside the Canvas directory > add a .gitkeep file inside it > Commit and Push
Check if files are live Paste the raw URL into Safari. You should see the image alone with no GitHub chrome around it.
Someone else pushed changes you do not have yet Click Fetch origin in GitHub Desktop, then Pull origin if new changes appear

Never rename or move an image file after it has been pushed and its URL has been used in a Canvas page. Canvas pages contain hardcoded raw URLs. Renaming a file breaks every page that references it with no warning and no error message. To update an image, replace the file in place using the exact same filename.
