Canvas Naming System: Option D (Permanent Standard)

ALL Canvas modules and pages across all 12 DAPR courses use Option D naming. No other system is in use.

Module title pattern: Topic: M# - Descriptive Title (Week ##)

Page name pattern: Topic: Descriptive Page Title

The three rules:

Rule 1 - Module title carries the topic prefix, module number, descriptive title, and week in parentheses. Example: Sound: M2 - Sound and Hearing (Week 02)

Rule 2 - Page name carries only the topic prefix and a plain descriptive title. No module number. No week. No part number. Example: Sound: Read Sound and Hearing

Rule 3 - At semester rollover, update only the week parenthetical in module titles if pacing changed. Never rename pages. Pages have no week reference and require zero rollover maintenance.

GitHub Folder Naming Rule: Underscores vs. Hyphens

Underscores _ connect words within one concept
Use underscores when multiple words form a single concept title inside a folder name.

sound_and_hearing - one concept
address_resolution_protocol - one concept
the_decibel - one concept
working_in_the_industry - one concept
dynamic_host_configuration_protocol - one concept
Hyphens - separate distinct segments from each other
Use hyphens between the topic prefix and the concept title in a folder name.

sound-the_decibel - topic and concept are two segments
networking-address_resolution_protocol
jobs-working_in_the_industry
dapr-2000 - course prefix always hyphenated
dapr-2000l - course prefix always hyphenated

Folder name pattern: topic-concept_title
The folder name is derived from the Canvas page name. Strip the colon, lowercase everything, replace spaces with underscores within the concept title, and put a hyphen between the topic and the concept. The week from the module title is never included in any folder name. Folder names are permanent once a URL has been used in a Canvas page.

Note: Always use raw.githubusercontent.com not github.com. Verify every new URL in Safari or Chrome before building the Canvas page. You should see the image with nothing else around it.

All/ - Shared Across Multiple Courses

All/ - Images referenced in more than one course
  • All/ProToolsCleanup/ legacy - keep original casing, do not rename
  • All/topic-concept_title/ all new shared folders follow the topic-concept_title pattern

Use All/ only when the same image appears in pages across two or more different courses. If an image is used in only one course, it belongs in that course folder even if the topic is general.

The Five Questions - Asked Every Time Images Are Involved

Question 1
Is this image shared across multiple courses, or does it belong to one specific course? Shared = All/    One course = dapr-XXXX/
Question 2
What is the exact course folder name? (dapr-2000, dapr-2000l, dapr-2255, dapr-3345, etc.)
Question 3
What is the Canvas page name this image belongs to? Apply the Option D conversion rule to derive the subfolder name: strip the colon, lowercase everything, underscores within the concept title, hyphen between topic and concept.
Question 4
What are the exact filenames of the images that have been pushed to the repository? List all of them before any HTML is written.
Question 5
Have these files been committed and pushed in GitHub Desktop? Confirm the push completed before any HTML is written.

Never rename or move an image file after its URL has been used in a Canvas page. Canvas pages contain hardcoded raw URLs. Renaming breaks every page that references the file with no error message and no warning. To update an image, replace it in place using the exact same filename.
