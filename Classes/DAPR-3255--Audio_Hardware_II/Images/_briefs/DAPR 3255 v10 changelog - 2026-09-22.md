## 2. This is a standards question, and it is yours

Standards 20.5 says "ask for no text at all", and it is right about why: twelve of
the first twenty eight DAPR 2255 images failed and every single failure was text.
Clipped, overprinted, or silently dropped.

But that rule is aimed at a figure whose subject is a **shape**. A current path, a
bell curve, a funnel, a pipe. For a figure whose subject **is its labels**, an
address anatomy, a layer stack, a decision tree, a comparison scatter, the rule
deletes the content and leaves the decoration.

20.5 needs that distinction written into it. I am not going to write it for you,
because it is a standards decision that will govern both courses and every future
brief. What I would suggest, for you to accept or rewrite:

> A figure whose teaching content is its labels is exempt from the no-text rule.
> Ask for the labels, keep the count to what will fit, and reject the render if a
> single label is clipped, overprinted or missing. A figure whose teaching
> content is a shape asks for no text at all.

## 3. Preflight rule 20.5d, so this cannot happen silently again

Neither gate compared a figure against the generation it replaced, which is why
v9 shipped. New rule: a build hard fails if it places a figure carrying no labels
while an older generation of the same figure carries them.

The rule needs to know how much text each figure holds, which means OCR, which
is not available everywhere preflight runs. So it reads a census file the image
repo carries, and the severity is split deliberately:

- **hard fail** when the census shows a placed figure lost its labels
- **warning** when the census is missing or incomplete, so the gate still runs
  for anyone who has not done the OCR step

Proved three ways: passes on the reverted build, hard fails when I move the ping
page back onto the unlabelled `-02` and names the figure and both character
counts, and warns without failing when the census is absent.

build anything:
