Installing Software: DMG, APP, and PKG

Getting software onto a Mac almost always means working with three things: a DMG that delivers it, an APP that you actually run, and sometimes a PKG that installs it into places a simple drag cannot reach. Windows software works differently enough that treating an EXE as a Mac equivalent causes more confusion than it resolves.

What a DMG Actually Is

A DMG is a disk image. Double-clicking one mounts a virtual disk on your desktop and in the Finder sidebar, exactly like inserting a physical disk. Most DMGs contain nothing but the app itself and a shortcut arrow pointing at the Applications folder. "Installing" the app means dragging it onto that arrow - there is no installer program running, no script executing, and no separate uninstall step beyond dragging the app to the Trash later. A DMG is a delivery container, not itself the final installed location of anything - once you have dragged the app out of it, the mounted DMG can be ejected and the downloaded .dmg file thrown away.

The App Store

The Mac App Store skips DMGs and PKGs entirely. Clicking Get or Install downloads and places the app directly into your Applications folder, keeps it updated automatically, and ties its license to your Apple Account rather than a serial number you have to track yourself. Not every piece of software this program uses is available there - Pro Tools and most professional audio software are not - but for everyday utilities it is often the simplest path.

Where EXE Fits In

An EXE is a Windows executable format - not a Mac installer choice at all, and not a direct equivalent to anything covered on this page. macOS cannot run an EXE under any circumstances; it is built for an entirely different operating system, not just a different container format. If you ever see a .exe file, it is Windows-only software, full stop.

Three Mac concepts, not two Mac-vs-Windows ones.
DMG, APP, and PKG are the three things to actually know on a Mac. A DMG is just a container for delivering files. An APP is the program itself. A PKG is an installer program that actively does something - the closest match to a Windows EXE, covered next.

When a Mac App Needs More Than a Drag

Some software has to place files in protected system locations that a simple drag-and-drop cannot reach - audio interface drivers, Audio Unit plug-ins inside /Library/Audio/Plug-Ins, or components that need to register with the operating system. For that, Mac software uses a .pkg installer, built with Apple's Installer.app format.

.pkg installer - runs a scripted install, can write to system-level folders, and asks for your admin password - the closest functional match to a Windows EXE. A .pkg is frequently bundled inside a DMG alongside, or instead of, a plain .app.

Only download installers from the developer's own site.
A Gatekeeper warning that a file "cannot be opened because it is from an unidentified developer" exists to protect you from exactly this. Never bypass that warning for software from a source you have not verified.

Real-World Examples

Not every DMG looks the same. These four are all real installers, and each does something slightly different.

Skim: the classic pattern. Drag the app icon onto the Applications shortcut and the install is finished.

Dropbox: instead of dragging, you double-click the icon directly, which runs a short first-time setup before placing the app.

Apogee Control 2: a .pkg installer for the driver, plus something rare on a Mac - a dedicated uninstaller app, included specifically because a driver-level install needs a clean way back out.

AIR Effects Bundle: nothing to drag at all - just a .pkg. Double-clicking it runs the scripted install directly.
