System Information, Activity Monitor, and Console

Three built-in apps answer three different questions about your Mac: what hardware is actually connected, what is using resources right now, and what has the system been logging in the background. Learning all three turns troubleshooting from guesswork into a process.

System Information

Open it from the Apple menu > About This Mac > More Info > System Report, or search for it directly in Spotlight. The sidebar organizes every category of hardware and software on the Mac - Hardware (CPU, Memory, Storage, USB, Thunderbolt/USB4, Audio, Bluetooth, and more), Network, and Software.

The USB category, expanded to show every hub and device in the chain, along with each device's connection type and link speed.

This view lists every connected USB device in a tree, including hubs, along with the link speed each one is negotiating - 5 Gb/s or 10 Gb/s, for example. This is the first place to check when Pro Tools does not see an interface: if the device is missing here entirely, the problem is a cable, a port, or power - not Pro Tools.

Windows equivalent.
Windows' closest match to this hardware tree is Device Manager. The Windows "System Information" app (run via msinfo32) is closer to a general system summary than to the detailed hardware tree shown here.

Activity Monitor

Open it from Applications > Utilities > Activity Monitor. Five tabs - CPU, Memory, Energy, Disk, and Network - each sort every running process by that specific resource.

The CPU tab, sorted by % CPU, with the system-wide load summary at the bottom.

% CPU / CPU Time - how much processing power a process is using right now, and its running total since it launched.
Threads / Idle Wake Ups - how many parallel execution paths a process is using, and how often it wakes the CPU from an idle state - a high wake count can point to a background app draining resources unnecessarily.
PID / User - the process's unique ID number, and which account owns it.
Real Mem / Private Mem - how much RAM the process is actually using right now, versus memory only that process can access.

When Pro Tools' meters spike or an interface glitches, sort the CPU tab by % CPU to find whichever background process is stealing processing power. The summary bar at the bottom - System, User, and Idle percentages, plus total Threads and Processes - shows at a glance whether the whole Mac is under real load or one runaway app is the culprit.

The Other Four Tabs

Memory - shows a Memory Pressure graph at the bottom: green means plenty of headroom, yellow means macOS is starting to work harder to manage memory, and red means it is actively struggling and swapping to disk - the exact moment a session starts to stutter.
Energy - ranks processes by power impact, most useful for tracking down what is draining a laptop battery fast.
Disk - shows read and write activity per process, useful when session playback stutters and RAM is not the bottleneck - the drive itself might be.
Network - shows data sent and received per process, useful for catching a cloud-sync app or an auto-updater competing for bandwidth or system resources mid-session.
Applications vs. background processes.
Activity Monitor lists both at once, with no visual separator by default. An application is something you opened yourself and see in the Dock; a background process is everything else - system services, Launch Agents, helper apps - running without ever appearing as a window. A process consuming heavy CPU without a Dock icon to match is almost always a background item worth investigating, not a bug in Activity Monitor.

Console

Open it from Applications > Utilities > Console. Console reads the system log - every message macOS and its apps write about what they are doing, including errors and crash reports.

Console before pressing Start streaming. The sidebar lists connected Devices, and Reports for Crash, Spin, Log, and Diagnostic reports.

Devices - the Mac itself, plus any connected iOS devices, each with its own log stream.
Reports - Crash Reports, Spin Reports, Log Reports, and Diagnostic Reports - saved records rather than a live stream.
Streaming live logs affects performance.
Console warns that streaming log messages will impact system performance. Turn streaming on only while actively troubleshooting a specific problem, not as a background habit.

After a Pro Tools crash, Console's Crash Reports section under Reports holds a detailed log of exactly what failed - the single most useful place to look before contacting support.

Work from hardware down to software.
Check System Information first to confirm a device physically exists and is recognized. Check Activity Monitor next to see what is actually running. Check Console last to read what the system logged about it. That order narrows a problem fastest.
