Privacy and Security

Every piece of hardware and software that needs deep access to your Mac - a microphone, a camera, an audio interface driver - has to get your explicit permission first. This page covers where that permission lives and how driver installation actually works underneath it.

The Privacy and Security Pane

Open System Settings > Privacy & Security. This pane gates which apps can access sensitive hardware and data: Microphone, Camera, Screen Recording, Full Disk Access, Accessibility, and Files and Folders each get their own list of allowed apps.

Microphone - required by Pro Tools and many audio interfaces for input monitoring. If input monitoring silently fails, check whether access was ever denied here.
Accessibility - required by some control surface software and MIDI utilities that need to observe or control other apps on the Mac.
Full Disk Access - required by some backup and file-management utilities to read protected system locations.
A silent denial looks identical to a bug.
If Pro Tools or a plug-in never even asks for a permission and simply does not work, the most likely explanation is that permission was denied once, in the past, and macOS is not asking again.

Gatekeeper

Gatekeeper is the layer that warns you when opening software from a developer Apple has not verified. The warning reads that the app cannot be opened because it is from an unidentified developer. After that first block, the same app can be allowed manually from the Security section of Privacy & Security.

Installing Drivers: Kernel Extensions vs. System Extensions

Audio interface drivers used to install as Kernel Extensions, or kexts - code running with full access to the operating system's core, the kernel. That access is powerful, but a faulty kext can crash the entire Mac, not just one app.

Modern macOS pushes hardware vendors toward System Extensions instead. A System Extension provides similar functionality without full kernel-level access, running in a more contained, safer space.

Approving a Newly Installed Driver

macOS blocks a newly installed driver until it is approved manually. The typical sequence is install, restart, open Privacy & Security, click Allow next to the blocked extension, then restart again.

Skipping approval is the most common cause of a driver that installs but does nothing.
A brand-new audio interface driver can install successfully and still leave the interface invisible to Pro Tools if the approval step in Privacy & Security was never completed.

Privacy Permissions vs. File-System Permissions

The word "permissions" means two unrelated things on a Mac, and mixing them up leads to looking in the wrong place entirely. Privacy permissions - Microphone, Camera, Accessibility, Full Disk Access, Files and Folders - control which apps are allowed to access specific hardware or protected data, and they live in Privacy & Security, covered above.

File-system permissions are a completely different concept: they control who can read, write, or execute a specific file or folder, and they live in Finder, under Get Info > Sharing & Permissions. Every file and folder has an owner, a group, and an "everyone" setting, each with its own Read, Write, or No Access level. A permissions problem here looks different from a privacy problem - instead of an app asking for access, you get an error trying to save, move, or delete a file because your account does not have Write access to it.
