Files, Folders, Applications, Packages, and Aliases

Finder shows several different kinds of things that all look similar at a glance - an icon and a name - but behave in genuinely different ways underneath. Telling them apart correctly prevents a lot of confusion later in this unit.

Six Things That Can Sit in a Finder Window

File - a single unit of data - a document, an audio file, an image.
Folder - a container that holds files and other folders, with no content of its own.
Application - a program you run, most often appearing as a single icon even though it is really a package underneath - see below.
Package (or bundle) - a folder disguised, on purpose, as a single file. Every application on the Mac is actually a package holding its real code and resources inside.
Alias - a pointer to another file or folder somewhere else, marked with a small arrow badge on its icon. It takes almost no space and does not duplicate anything.
Disk image / installer package - a .dmg mounts as a virtual disk, and a .pkg runs a scripted install - both covered in full on the Installing Software page.

Looking Inside a Package

Control-click any application and choose Show Package Contents. Finder opens the package as an ordinary folder, revealing a Contents folder inside holding pieces like MacOS (the actual program code), Resources (icons, sounds, images the app uses), and Info.plist (a small file describing the app to macOS). This is exactly how a single application icon can actually contain hundreds of internal files while still behaving like one double-clickable item.

Look, do not touch.
Opening a package's contents to understand how it is built is completely safe. Moving, renaming, or deleting anything inside it is not - a package with a missing internal file usually stops working entirely, sometimes without a clear error message explaining why.

Control-click on a real app - Show Package Contents sits right below Open.

Inside: Resources, MacOS (the actual program code), _CodeSignature, Info.plist, and CodeResources - exactly the internal structure described above, on a real installed app.

Aliases vs. the Real File

An alias looks almost identical to the file it points to, but a small arrow badge in the corner of its icon gives it away. Double-clicking an alias opens the original file, wherever that original actually lives - the alias itself holds no real content. Deleting an alias does nothing to the original file. Deleting or moving the original, however, breaks every alias pointing at it, leaving each one pointing at nothing until it is either fixed or removed.

A real alias - the small arrow badge in the bottom-left corner is the only visual difference from the original folder it points to.
