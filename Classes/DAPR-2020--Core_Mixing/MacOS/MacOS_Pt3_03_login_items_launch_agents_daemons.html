Login Items, Launch Agents, and Launch Daemons

Some apps start themselves the moment you log in, and some run in the background permanently without ever opening a window at all. Both behaviors are controlled by the same underlying system, visible at two different levels - one you manage yourself, and one macOS manages for every app that asks.

Login Items and Background Items

System Settings > General > Login Items & Extensions lists every app set to open automatically when you log in, plus every background item currently running that did not need you to open anything at all. The "Open at Login" list is one you edit directly - add an app you want to start automatically, or remove one you are tired of seeing launch every morning. The background items list below it is different: it shows helper processes and extensions that other apps installed and manage themselves, which is exactly why an audio interface's control panel, or a plug-in license manager, can be running even when you have never manually opened it and its main app is not on screen.

Login Items are the visible surface of a bigger system.
Everything listed under background items in Login Items & Extensions is, underneath, either a Launch Agent or a Launch Daemon - the two mechanisms covered for the rest of this page. Login Items & Extensions is the friendly front door; Launch Agents and Launch Daemons are the actual machinery behind it.

A real Login Items & Extensions panel - the Open at Login list above, and App Background Activity toggles below, each one a background item running on its own.

What launchd Actually Does

launchd is the first process macOS starts at boot, and it never quits. Every other background process on the Mac - system service or third-party helper - is started, supervised, and eventually stopped by launchd, based on the instructions written inside a .plist configuration file.

Launch Agents

A Launch Agent runs inside a logged-in user's session. It can draw a window, show a menu bar icon, or ask for input, because it has access to that user's full desktop environment. Agents start after login, and if two accounts are logged in on the same Mac, each gets its own separate copy of the same agent.

~/Library/LaunchAgents - agents that belong to your user account only.
/Library/LaunchAgents - agents installed for every account on the Mac, though each still runs separately per logged-in user rather than as one shared process.
/System/Library/LaunchAgents - Apple's own agents, protected by System Integrity Protection.

Launch Daemons

A Launch Daemon runs as root, with no user session and no ability to show a window. Daemons start at boot, before anyone logs in, and keep running even if every user logs out. There is no per-user LaunchDaemons folder - a daemon is system-wide by definition.

/Library/LaunchDaemons - third-party daemons - most audio interface drivers install one here.
/System/Library/LaunchDaemons - Apple's own system services, protected by System Integrity Protection.
The short version: An Agent runs as you, can show UI, and starts at login. A Daemon runs as root, shows nothing, and starts at boot.

Who Installs These, and Why

Audio interface driver installers (Focusrite, Universal Audio, RME, and similar), the iLok License Manager, and Adobe and Microsoft update helpers all drop a Launch Agent or Launch Daemon during installation. That is how they keep running quietly in the background instead of requiring you to open them by hand every time you turn the Mac on.

Watch for this in troubleshooting.
A stuck or corrupted Launch Agent is one of the most common reasons a plug-in or audio interface refuses to authorize, or a Mac feels slow immediately after login.

Inspecting and Managing Them

launchctl list - run in Terminal, prints every Launch Agent currently loaded for your user account.
Activity Monitor - shows every running process, agent or daemon, under the Process Name column, with its parent process visible.
launchctl bootout - unloads a specific Launch Agent or Daemon by its .plist path, stopping it until the Mac restarts or it is reloaded.

A real launchctl list output. Recognizable entries like com.noodlesoft.HazelHelper and com.audinate.dante.DanteVia.DanteViaLoader show exactly the kind of third-party Agent covered above.

This only shows Agents, not Daemons.
A plain launchctl list run as yourself lists Agents running in your own session. Root-level Daemons do not show up here - seeing those requires running sudo launchctl list instead.
Tip: Do not remove a Launch Agent or Daemon you do not recognize without researching the name first. Some are essential to macOS itself, and Apple's own agents in /System are protected from casual deletion anyway.
