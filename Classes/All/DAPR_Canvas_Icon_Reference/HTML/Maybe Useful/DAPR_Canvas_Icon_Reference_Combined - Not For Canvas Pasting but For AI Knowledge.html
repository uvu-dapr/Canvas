DAPR Canvas Icon System

Audio Program  |  Utah Valley University  |  Complete AI Reference

This document is the authoritative reference for every icon, callout box, and submission row used in DAPR Canvas HTML pages. It is written for AI tools and instructors alike. Section 1 explains the Canvas HTML environment and what does and does not work. Section 2 covers the critical SVG rule. Sections 3-6 define every icon with its colors, file, and copy-paste template. Section 7 is a decision guide. Section 8 covers the GitHub image repository. Read Section 1 and Section 2 before generating any Canvas HTML.

Section 1 - Canvas HTML Environment Rules for AI

Canvas is a filtered HTML environment. It strips disallowed tags and attributes on save. AI-generated HTML must follow these rules exactly or content will break silently with no error message.

What Canvas Strips on Save

Element / PropertyWhat Happens
<style>...</style>Removed entirely
<script>Removed for security
<html>, <head>, <body>Stripped - paste body content only
<svg> tagStripped - svg is not on the Canvas allowed tag list. Use <img> instead.
External CSS (<link>)Removed entirely
Google Fonts / @font-faceBlocked
CSS variables (--var)Not supported
JavaScript event handlersStripped

What Canvas Allows

Element / PropertyNotes
Inline style=""The only reliable CSS method
display:flexOn the Canvas style allowlist - works reliably
display:gridOn the allowlist - use with caution on older builds
<img src="...">Required alt attribute. Use for all icons.
<table>Data and layout. Use role="presentation" for layout.
<h2> - <h6>Never use H1 - Canvas owns H1 for the page title
border-radius, flexBoth on the official style allowlist
All standard block/inline elementsdiv, p, span, ul, ol, li, a, strong, em, hr, br, blockquote, pre, code

Required - Accessibility standard: Every Canvas page must pass the Canvas Accessibility Checker with zero issues before publishing. Run the checker after every paste. The checker icon is the person-in-a-circle at the right end of the Rich Content Editor toolbar.

Critical - Never use #CC4400 or #E65100 as text color. Both fail or get flagged by the Canvas accessibility checker. Use #993300 for any orange-toned body text. #E65100 is only safe as an SVG stroke color inside a colored icon circle - never as a text color or heading color.

Section 2 - The SVG Rule: Why Icons Use <img> Not <svg>

Critical - <svg> is not on the Canvas allowed HTML tag list. Canvas strips the entire <svg> element on save. The callout box colored div survives. The icon inside it disappears. This is silent - no error message, no broken image indicator, just empty space. All icons in Canvas pages must be <img> tags. Never use inline <svg> in Canvas HTML.

Wrong - Inline SVG (stripped by Canvas)

<div style="background-color:#E8F5E9; border-left:4px solid #1B5E20; padding:12px 16px; margin:16px 0; display:flex; align-items:flex-start; gap:12px;">
  <svg viewBox="0 0 24 24" width="22" height="22" fill="none" stroke="#1B5E20">
    <path d="M12 22s8-4 8-10V5l-8-3..."/>
  </svg>
  <p style="margin:0;"><strong>Required:</strong> Text here.</p>
</div>

RESULT: Colored box renders. SVG disappears entirely.

Correct - <img> pointing at GitHub raw URL

<div style="background-color:#E8F5E9; border-left:4px solid #1B5E20; padding:12px 16px; margin:16px 0; display:flex; align-items:flex-start; gap:12px;">
  <img src="https://raw.githubusercontent.com/uvu-dapr/
Canvas/main/Classes/All/DAPR_Canvas_Icon_Reference/
Callout_Required.svg"
       width="22" height="22"
       alt="Required icon"
       style="flex-shrink:0; margin-top:2px;">
  <p style="margin:0;"><strong>Required:</strong> Text here.</p>
</div>

RESULT: Colored box renders. Icon renders. Zero issues.

Warning - SVG stroke colors and <img> tags: When an SVG file is loaded via <img>, the stroke color is baked into the file. You cannot override it with CSS. This matters for the feedback table header icons - they appear on dark colored backgrounds and need white (or dark on gold) strokes baked into the file. The repository contains two versions of each feedback icon: the original colored-stroke version for use on white backgrounds, and a white/dark-stroke version for header cells. See Section 6 for details.

Section 8 - GitHub Image Repository Rules

All images used in Canvas pages - including icons - are hosted in the public GitHub repository uvu-dapr/Canvas. Images are referenced via raw GitHub URLs. They are never embedded as base64 or uploaded to Canvas Files.

RuleDetail
Always use raw.githubusercontent.comNever use github.com URLs - those show the GitHub file browser, not the image. Verify every new URL in a browser before building the page.
Never rename or move a file after its URL is in a Canvas pageCanvas pages contain hardcoded URLs. Renaming breaks every page that references the file with no error message. To update an image, replace it in place with the same filename.
Confirm filenames before writing img tagsNever guess a filename. Confirm the exact filename has been pushed to GitHub. A page built with assumed filenames will have silently broken images.
Folder structure: course / assignment subfoldercourse folder = dapr-2000, dapr-2000l, etc. or All/ for shared. assignment subfolder = lowercase, underscores within concept words, hyphens between segments.
Alt text under 120 charactersCanvas accessibility checker flags alt text over 120 characters.
Images must be pushed before HTML is writtenRaw URLs are live immediately after pushing via GitHub Desktop. Verify at least one URL in a browser before writing img tags.

Section 9 - AI Generation Checklist

Before delivering any Canvas HTML, verify every item below. Content that fails any of these cannot be published.

#CheckWhy It Matters
1No <svg> tags anywhere in the outputCanvas strips the entire <svg> element silently. Use <img> for all icons.
2No <style> blocks, no external CSSCanvas removes style blocks. All CSS must be inline style="" attributes.
3No <html>, <head>, or <body> tagsPaste only body content into Canvas.
4First heading is H2, not H1Canvas provides H1 from the page title automatically. Content starts at H2.
5Heading levels never skip (H2 to H4 without H3)Panorama and Canvas checker both flag skipped heading levels as Severe.
6All <img> tags have alt="" attributeMissing alt text is flagged as Severe. Informational images need description. Decorative use alt="".
7All <a> tags have title="destination" attributeCanvas accessibility checker flags links without descriptive titles.
8No #E65100 or #CC4400 as text colorBoth get flagged by the Canvas checker. Use #993300 for orange-toned text.
9No white text on gold (#F9A825)White on gold = 2.9:1 contrast. Fails WCAG AA. Always use #212121 on gold.
10Data tables have <caption> with no style attribute + <th scope="col">Both are required independently. Missing either one is a separate checker error.
11Layout tables have role="presentation"Without this, Canvas evaluates them as data tables and flags missing headers.
12Icon img tags use the correct GitHub raw URLOnly raw.githubusercontent.com serves the image directly. Confirm filenames are pushed.
13Feedback table header icons use the _white or _dark stroke versionStandard stroke icons are invisible against their matching-color header backgrounds.
14All colors are hex codes, no rgba()Hex is easier to contrast-check and consistent with the approved color list.
15No "All of the above" or "None of the above" in quiz questionsProhibited by program policy. Rewrite as independent distractors.
16No em dashes and no double hyphens (--) in visible page contentUse hyphen with spaces ( - ) as a separator in running text.
17Submission instructions state exact filename for every deliverableStudents should never have to infer what to name their files. Show an example filename.
